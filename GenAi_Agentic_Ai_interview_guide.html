01
Foundation

LLM – Large Language Model

Interview answer: An LLM is a machine-learning model trained on large datasets to understand and generate language. Most modern LLMs use Transformer-based architectures and generate text by predicting tokens based on context.
Input textUser prompt
→
TokenizationText → tokens
→
TransformerAttention & layers
→
OutputGenerated tokens

Key concepts

ConceptMeaning
TokenA unit of text processed by the model; it may be a word, part of a word or punctuation.
TransformerNeural-network architecture used by many modern language models.
AttentionMechanism that helps the model weigh relationships between tokens.
InferenceUsing a trained model to generate a prediction or response.
EmbeddingNumerical vector representation of information.
Q: What is the difference between Generative AI and an LLM?
Generative AI is the broader category of systems that generate content such as text, images, audio or video. An LLM is a type of model focused primarily on language tasks.
Q: Does an LLM search the internet by default?
No. It generates from its learned parameters and the context supplied to it. Current external information requires an integrated search or data-retrieval capability.

Examples: GPT, Gemini, Claude and Llama model families.

02
Context management

Tokens & Context Window

Interview answer: Tokens are the units of text a model processes. The context window is the maximum amount of input and output token context the model supports for a request or conversation.
Model context budget
↓
System instructionsRules and role
Conversation historyPrevious turns
Retrieved RAG chunksExternal knowledge
Current questionUser request
↓
Available generation budgetResponse tokens must also fit within model limits

How do you manage context-window limitations?

  • Retrieve only relevant document chunks rather than entire documents.
  • Limit or summarize older conversation history.
  • Use Top-K retrieval and reranking.
  • Remove duplicated or irrelevant context.
  • Track token usage and reserve space for the answer.
Q: Does Pinecone increase the context window?
No. Pinecone stores external vectors and retrieves relevant content. The retrieved content still has to fit within the LLM's context limit.
03
Generation control

Temperature

Interview answer: Temperature controls the randomness of token sampling during generation. Lower values generally produce more predictable output; higher values generally produce more varied output.

Low temperature

0.0–0.2

Often useful for extraction, classification and constrained responses.

Moderate temperature

0.3–0.7

Often useful for general explanations and conversational responses.

Higher temperature

0.8+

Can produce more varied or creative responses.

These are indicative ranges, not universal settings. Supported values and effects vary by model.

Q: Does temperature improve model intelligence or factual accuracy?
No. It changes sampling behaviour. Factual accuracy depends on the model, prompt, evidence, retrieval quality and validation.

Q: LLM vs embedding model?
An LLM generates or interprets language. An embedding model maps content into vectors used for similarity search and other downstream tasks.
05
Knowledge grounding

RAG – Retrieval-Augmented Generation

Interview answer: RAG combines information retrieval with LLM generation. It retrieves relevant information from an external knowledge source and provides it to the LLM as context before generating an answer.
Document ingestionPDF, Word, HTML, database
↓
Extract text → split into chunks
↓
Generate embeddings
↓
Vector store / search index
User question → query embedding
↓
Retrieve relevant chunks
↓
Context + question → LLM
↓
Grounded answer + sources

Why use RAG?

  • Answer using private or domain-specific information.
  • Update knowledge without retraining the LLM.
  • Provide traceable source references.
  • Reduce unsupported answers when retrieval and prompting are well designed.
Q: RAG vs fine-tuning?
RAG supplies external knowledge at inference time and is useful when information changes or must remain source-grounded. Fine-tuning changes model behaviour or task performance through training. They can be combined.

Naive RAG generally follows a fixed retrieval pipeline. Agentic RAG uses an agent to choose retrieval strategies or sources and can perform multiple retrieval steps based on intermediate results.

Document preparation

Chunking & Overlap

Interview answer: Chunking divides large documents into smaller sections so they can be embedded, indexed and retrieved independently.
Original document
↓

Chunk 2Sections 3–5
Chunk 3Sections 5–7
Chunk 4Sections 7–9

Overlapping sections preserve some context across chunk boundaries.

StrategyUse
Fixed-sizeSimple predictable chunk lengths.
RecursiveSplit by paragraph, sentence and other separators.
Sentence-basedKeep sentence boundaries where possible.
SemanticSplit based on changes in meaning.
Structure-awareRespect headings, tables and document sections.
Q: What happens if chunks are too large or too small?
Large chunks may contain irrelevant material and consume more context. Small chunks can lose surrounding meaning. Tune chunk size and overlap with retrieval evaluations.

Q: Pinecone vs context window?
Pinecone is external storage and retrieval infrastructure. The LLM context window is the model's working token capacity. Pinecone helps select relevant information; it does not expand that capacity.

Design note: Enforce tenant and document-level authorization in retrieval filters and application policy. A namespace alone should not be treated as the complete security boundary.

09
Candidate retrieval

Top-K Search

Interview answer: Top-K search returns the K highest-ranked candidates from a retrieval operation, such as the most similar chunks for a query embedding.

K = 1

One candidate. Focused but may miss supporting context.

K = 3–5

Small candidate set, often a useful starting experiment.

K = 10+

More coverage, but may include irrelevant material and increase cost.

Tune empirically

Use evaluation data, query types and context budget.

Q: How do you choose K?
Evaluate retrieval precision and recall, chunk size, query complexity, context budget, latency and downstream answer quality. K should be tuned, not selected by a universal rule.
10
Retrieval refinement

Reranking

Interview answer: Reranking is a second-stage process that reorders retrieved candidates based on their relevance to the specific query.
User query
↓
Vector / hybrid search retrieves top 20 candidates
↓
Reranker scores query-document relevance
↓
Best 3–5 chunks sent to LLM
Vector searchReranking
Initial candidate retrieval.Second-stage refinement.
Often uses embedding similarity.Often uses cross-encoder relevance scoring.
Efficient for broad search.More computationally expensive per candidate.

Examples: Cohere Rerank, BGE Reranker and cross-encoder models.

Q: Why rerank if vector search already ranks results?
Initial vector ranking is a fast candidate retrieval step. A reranker can compare each candidate more directly with the query and improve the ordering of context passed to the LLM.

Combined retrieval

Hybrid Search

Interview answer: Hybrid search combines lexical or keyword retrieval with semantic vector retrieval, then merges or reranks the results.

Q: When is hybrid search useful?
When a question contains exact identifiers, product codes, names or technical terms as well as natural-language meaning. Keyword search can find exact matches while vector search finds semantically related content.

Action execution

Tool Calling & Agent Loops

Interview answer: Tool calling lets an LLM request a predefined function or external capability. The application validates the request, executes the tool and returns the result to the model.
User request
↓
LLM chooses tool and arguments
↓
Application validates tool name and arguments
↓
Python function / API executes
↓
Tool result returned to LLM
↓
Final answer or another tool request

Example tools

Calculator – deterministic arithmetic
Weather API – current weather
Database query – approved data retrieval
File search – locate allowed documents
Q: Tool calling vs agent?
Tool calling is the mechanism for requesting external functions. An agent uses reasoning, tool selection, execution, observation and repeated decisions to complete a task.
Q: Does the LLM execute Python code directly?
No. The LLM requests a tool call. The host application validates and executes the mapped function. Never execute arbitrary model-generated code without strict isolation and controls.

Integration protocol

MCP – Model Context Protocol

Interview answer: MCP is an open protocol that standardizes how AI applications connect to external tools, resources and prompt templates.

↓

↓

PrimitivePurposeExample
ToolsPerform an action.Create a ticket or query a service.
ResourcesExpose contextual data.Read an approved project document.
PromptsOffer reusable prompt templates.Code review instructions.
Q: MCP vs traditional tool calling?
Traditional tool calling often uses application-specific schemas and integrations. MCP standardizes how compatible clients discover and communicate with servers exposing tools and resources. An LLM can still use tool calling to select an MCP capability.
Q: Does MCP replace APIs or function calling?
No. MCP is a protocol layer for integration. MCP servers may call APIs internally, and an LLM application may use function/tool calling to decide which MCP capability to invoke.

Q: Do multi-agent systems require different LLMs?
No. Multiple agents can use the same model with different roles and permissions. Different models may be chosen based on reasoning needs, latency and cost.

Design caution: More agents can increase latency, cost and coordination complexity. Use multiple agents only when task separation provides measurable value.

19
Safety & governance

Guardrails

Interview answer: Guardrails are controls that enforce security, safety, validation and execution policies around an LLM application. They should be implemented in application logic and infrastructure, not only in prompts.

Input validation

Reject empty, malformed or oversized requests.

Prompt-injection defense

Treat retrieved content as untrusted data; enforce instruction hierarchy.

Output validation

Validate schemas, content and allowed formats.

PII protection

Detect, mask or restrict sensitive information.

Tool permissions

Allowlist tools and validate arguments.

Human approval

Require confirmation for sensitive or irreversible actions.

Q: Why is a system prompt not enough?
A prompt is an instruction to the model, not an enforcement boundary. Critical controls require authentication, authorization, validation, isolation and application-level policy checks.

Multi-LLM Architecture

Interview answer: A multi-LLM architecture uses multiple model calls or models with distinct responsibilities, such as task routing, research, generation and evaluation.

Q: Why use one model for routing and another for evaluation?
Separating responsibilities can improve control and create an independent review stage. A smaller model may handle simple routing, while a stronger model evaluates complex evidence. It adds cost and latency, so measure the benefit.
Q: Does a separate evaluator guarantee correctness?
No. Evaluators can make mistakes. Use explicit criteria, source evidence, deterministic checks where possible, representative datasets and human review for critical decisions.

Interview-ready summary

LangChain helps connect LLM application components. LangGraph manages complex stateful agent workflows. LangSmith provides tracing and evaluation. MCP standardizes how AI applications connect to external capabilities. They complement one another rather than directly replacing one another.

Solution architecture

Enterprise Agentic RAG Architecture

Scenario: Design an enterprise assistant that reads internal documents, searches the web, performs calculations, accesses approved business systems and generates verified answers.
User / Enterprise UI
↓
Identity, access control and input guardrails
↓
Supervisor / LangGraph orchestration
↓
Internal RAGEmbedding + Pinecone
External researchTavily search
Enterprise toolsMCP integrations
Business APIsApproved actions
↓
Top-K retrieval + hybrid search + reranking
↓
LLM generation with grounded context
↓
Evaluator + output guardrails + human approval
↓
Final answer with evidence and sources

Cross-cutting: LangSmith tracing, Evals, monitoring, audit logs, cost and latency controls.

How to answer this architecture question

  1. Ingestion: Extract text from PDFs and business documents, preserve structure and metadata, and process documents asynchronously.
  2. Indexing: Chunk documents, generate embeddings in batches and store vectors with metadata in a vector database.
  3. Security: Authenticate users and enforce document-level permissions during retrieval.
  4. Retrieval: Apply metadata filtering, hybrid search, Top-K retrieval and reranking.
  5. Orchestration: Use a supervisor and graph workflow when the task requires multiple steps or tools.
  6. Generation: Pass only relevant context to the LLM and request evidence-backed responses.
  7. Tools: Connect approved enterprise capabilities through APIs or MCP.
  8. Quality: Evaluate retrieval and answer quality, and use human review for high-impact actions.
  9. Operations: Trace latency, errors, token use, cost and user feedback.
Q: How would you support 100,000 documents and a five-second response target?
Separate offline ingestion from online query processing. Use batch and parallel ingestion, suitable indexing, metadata filters, efficient Top-K retrieval, reranking only where justified, caching, asynchronous I/O and model selection. Load-test the full path. Five seconds is a service-level target to validate, not a guarantee; network, retrieval, reranking and generation latency all contribute.
